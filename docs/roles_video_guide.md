# Обновление A4: демо-роли и видео проверки товара

Это пакет обновления существующего проекта `~/Downloads/a4`, а не новая база данных. Основан на загруженном архиве `inventory-app-a4.zip` и исправленных в чате ALT-описаниях. Состояние папки на вашем Mac напрямую не прочитано.

## Установка

1. Сохраните и распакуйте `a4_roles_video_update.zip` в Downloads. Получится `~/Downloads/a4_roles_video_update`.
2. В терминале, где работает `npm start`, нажмите **Control+C**. Postgres.app оставьте в состоянии Running.
3. Выполните:

```bash
python3 "$HOME/Downloads/a4_roles_video_update/apply_update.py" "$HOME/Downloads/a4"
```

4. Только после `UPDATE COMPLETE`:

```bash
cd "$HOME/Downloads/a4"
npm start
```

5. Откройте `http://localhost:3000`. Перезагрузите страницу, чтобы браузер получил новые HTML, CSS и JavaScript.

Не запускайте `schema.sql`, `seed.js`, `npm run schema` или `npm run seed`. Они относятся к созданию исходного набора данных, а не к обновлению.

Установщик требует уже существующие Node.js, express/pg/bcryptjs в node_modules, PostgreSQL 18 и FFprobe из FFmpeg. Новые npm-зависимости не добавляются. Если появляется ошибка, не продолжайте старыми командами инициализации: сохраните сообщение. Не выдавайте `UPDATE COMPLETE` за успешный запуск приложения — отдельно выполните проверки ниже.

| Роль в интерфейсе | Роль в БД | Email | Права |
|---|---|---|---|
| Administrator | owner | owner@shop.example | Продажи, поставки, коррекции; название, цена, порог пополнения; загрузка и публикация видео |
| Seller | employee | employee1@shop.example | Продажи и поставки; загрузка своего видео на проверку; без изменения цен, коррекций и публикации |
| Buyer | customer | customer@shop.example | Просмотр каталога и опубликованных видео, скачивание видео; без записи в складские данные |

Общий пароль: **Demo1234!**. Аккаунт можно нажать в компактной подсказке под Log in — поля заполнятся, затем нажмите Log in. Это вход в готовые аккаунты, а не открытая регистрация с выбором прав. Старые employee2–employee9 не удаляются.

Подсказка имеет размер 13 px и контрастный серый текст, а не нечитаемый микрошрифт. Сервер ограничивает действия независимо от того, видны ли кнопки. Роль повторно читается из PostgreSQL, а не принимается от браузера. Сессия хранится на сервере, cookie имеет HttpOnly и SameSite=Strict; срок — один час. Перезапуск Node завершает сессии. Продажа должна быть отрицательной, поставка положительной; коррекция доступна только администратору. Баланс и история меняются в одной транзакции.

Это локальный учебный режим, не готовая система для реальных покупателей. Общий пароль владельца нельзя выставлять в интернет или через публичный туннель. `DEMO_MODE=0` скрывает подсказки, но НЕ меняет уже созданные пароли. Для публичного размещения нужны индивидуальные учётные данные и отдельная проверка развёртывания, TLS, защиты загрузок и хранения файлов.

## Реальное видео внутри продукта

Продавец выбирает товар → **View** → **Upload a product check video**. Он прикрепляет свой MP4, вводит название и текстовое описание / полную расшифровку речи, указывает пример модели или конкретную единицу/партию и подтверждает права на запись. Рекомендуется короткая запись обычной работы устройства без посторонних людей и личных данных. Например, собственные наушники воспроизводят короткую собственную голосовую запись. Не используйте коммерческую музыку без разрешения.

Видео хранится в `storage/videos/`, а PostgreSQL содержит связь с товаром, автором, параметрами файла и статусом. Видео не дублируется в каждой строке каталога. До публикации его видят загрузивший продавец и администратор. Покупатель не получает неопубликованный ролик даже по прямому адресу. Администратор открывает тот же товар, нажимает **Review video**, просматривает запись, затем **Publish**, **Reject** или для опубликованного файла **Unpublish**. Решения сохраняются в журнале.

Покупатель открывает этот товар и нажимает **Watch**, затем Play. Есть **Download MP4** и раскрываемый текст **Transcript and description**. Автовоспроизведения нет; preload="none" — рекомендация браузеру не загружать видеоданные заранее, а не гарантия нулевых сетевых запросов во всех браузерах.

Ограничения: MP4 с H.264, yuv420p, AAC или без аудио, не более 60 секунд, 40 MiB и 1080p (горизонтально или вертикально). Расширение файла само по себе недостаточно: FFprobe проверяет потоки, размеры и длительность. Проверка контейнера/кодеков не является антивирусным сканированием; публичный сервис требует дополнительного усиления безопасности.

Видео демонстрирует конкретную модель или обозначенную единицу. Оно не подтверждает исправность всех товаров с таким SKU и не является независимой сертификацией. Новых «настоящих» видеопроверок в пакете нет: нужно загрузить вашу собственную запись.

### Если запись с iPhone имеет HEVC или MOV

Скрипт создаёт отдельную совместимую копию и не удаляет оригинал:

```bash
cd "$HOME/Downloads/a4"
python3 tools/prepare_product_video.py "/полный/путь/к/вашей/записи.mov"
```

Проще напечатать команду до пути и перетащить файл в терминал. На выходе будет файл с суффиксом `_web.mp4`. Запись длиннее 60 секунд скрипт не обрезает молча: сначала выберите нужный фрагмент в редакторе.

После перезапуска сервера видео и складские данные должны оставаться; войти в аккаунт потребуется снова.

## Какие исходники показывать преподавательнице

`public/index.html` — разметка форм и video; `public/styles.css` — оформление; `public/app.js` — выбор товара, запросы API, подсказки аккаунтов и проигрыватель; `server.js` — маршруты и проверка прав; `lib/security.js` — правила изменения остатков и видимости видео; `lib/video.js` — потоковое сохранение файла и FFprobe; `db.js` — ваше прежнее подключение; `sql/migrations/002_roles_video.sql` — расширение схемы без удаления товаров.

Короткое объяснение на английском:

> The seller uploads a product demonstration. PostgreSQL stores its product reference, uploader, description and publication status, while the MP4 is stored on disk. Only the administrator can publish the recording. Buyers can watch published clips but cannot change stock or upload files. Permissions are checked in the API, not only by hiding buttons.
